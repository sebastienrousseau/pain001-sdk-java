# AGENTS.md

`pain001-sdk-java` is the typed Java client for the pain001 REST API
(`pain001 serve`). It holds no payment logic: the server generates and
validates; this repository sends requests and maps responses to records.
It is proven by the shared conformance kit in `conformance/`. These are
the rules an automated change is most likely to break; humans follow
them too. Read [CONTRIBUTING.md](CONTRIBUTING.md) first.

## Versioning

- The version is `0.0.x`, moves by `0.0.1`, and ships in lockstep with
  the pain001 suite. Never bump it as a side effect of a change; the
  maintainer decides when a release opens.
- It is restated in `pom.xml` and `CITATION.cff`, with a `## [0.0.N]`
  heading in `CHANGELOG.md`.
- Work for the next version happens on `feat/v<next-version>`, the only
  pull request into `main`.

## Commits

- Conventional commits with a body that says why.
- Every commit is signed off (`git commit -s`, see [DCO.txt](DCO.txt))
  and SSH-signed. Never rewrite pushed history.

## The gate

- `make check` runs every local gate CI runs: whitespace format, the
  500-line file limit and `mvn -B verify` (javac `-Xlint:all -Werror`,
  unit tests, PMD complexity ceilings). With `PAIN001_BASE_URL` set,
  `make conformance` runs the kit and the typed tests against that
  server. "It compiles" is not done.
- Jackson stays behind the package-private `Json` class and the
  `JsonNode` values the public API already exposes; add no other
  runtime dependency.

## Data

- No real account numbers, personal data or bank-restricted material in
  the repository. Test inputs are the kit's synthetic fixtures.
- Never log request or response bodies.

## Leave alone

- `conformance/` is vendored from core, never edit it here. It changes
  only by copying core's kit at the matching version and regenerating
  `conformance/SHA256SUMS` (see CONTRIBUTING.md).
- `ci/server-requirements.txt` is generated by `uv pip compile`; never
  edit it by hand.
